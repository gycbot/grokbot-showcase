How it moves

一条时间轴，
三种动作。

Anime.js 4 的 createTimeline() 把多条动画排在同一条时间线上。位置参数可以是绝对毫秒，也可以是“上一条开始后 0.2 秒”。这样改节奏时只动一个数，不用去翻十几处 delay。

页面里的三段分别是：位移（红点从左到右）、描边（SVG 路径按长度长出来）、错峰入场（四个方块按 70ms 间隔落下）。它们共用同一条 seek，所以拖动进度时不会各走各的。

Grok Bot 在制作页面前会先出关键帧：0.0 秒是什么、2.3 秒是什么。构图和字号确认了，才把动作写成代码。这个顺序比“先写一堆动画再看效果”省时间。

0.0 s标题与红点落位MOVE
0.5 sSVG 路径开始描边DRAW
0.7 s四个方块错峰进入STAGGER 70
2.3 s第三帧文字与标签出现REVEAL
3.4 s停住，不循环抢注意力REST
Source / 可读的写法

先写顺序，
再写缓动。

这段是页面里真实使用的结构，省略了装饰元素。所有入场都只动 transform 和 opacity；线用 createDrawable()，不手算 dashoffset。

如果系统开了“减少动态效果”，页面直接给终态，不播这条时间轴。

// anime.js 4.5 · MIT
const tl = createTimeline({
  defaults: { ease: 'outExpo' }
});

tl.add('.f1 .dot', {
    x: [0, 150], scale: [.6, 1],
    duration: 900
  }, 0)
  .add(createDrawable('#drawPath'), {
    draw: ['0 0', '0 1'],
    duration: 1100
  }, 500)
  .add('.f2 .tile', {
    y: [10, 0], opacity: [0, 1]
  }, stagger(70, { start: 700 }));

// 拖动进度：同一条时间轴 seek
seek.oninput = e =>
  tl.seek(e.target.value * 3.4);
01 / 先定终态

最后一帧要是对的

先确认 3.4 秒停住的画面成立，再反推中间怎么走。终态不成立，动作越多越乱。

02 / 只动便宜的

transform 和 opacity

位置用位移，进度用 scaleX。不去动 top、left、width，滚动和手机构图都更稳。

03 / 留出静默

3.4 秒后停住

不循环、不呼吸、不抢注意力。需要重看时按“重播”，而不是让页面一直动。
