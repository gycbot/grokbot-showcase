委派链

交出去之前，
先把这四件事说清。

少一件，子代理就会用猜测补；补出来的东西，最后还要主线返工。

01 / SCOPE

拆边界

只做什么、不做什么。把「顺便也改一下」挡在门外。

scope: pages/04 only
02 / CONTEXT

给上下文

读哪些文件、参考哪一版、哪些事实已核实。

brief + owner_list + .skills
03 / RETURN

回传产物

交路径，不交形容词。页面、截图、笔记各在哪。

path + result + gap
04 / ACCEPT

主线验收

按验收锚点逐条核；缺项写缺口，不替它圆。

acceptance_anchors

边界

能交出去的，
和不能交出去的。

YES 适合委派

  • 可拆的一页页面、一组截图、一份笔记，边界能写清。
  • 可验的产物有路径、有规格，能逐项核。
  • 独立的不需要主人中途拍板，不需要登录。
  • 并行的两条线互不写同一个文件。

NO 不该委派

  • 要拍板的方向、口径、是否发布，得主人定。
  • 要登录的平台账号、支付、对外提交，不能交给子代理。
  • 拆不开的上下文强耦合，交出去反而多一轮解释。
  • 会撞车的多个代理写同一个文件，必须串行。

任务包

一份任务包，
让接手的人不用猜。

这不是某个系统的内部格式，是一条委派至少要说清的字段。可以直接照着写。

task / 04-anything2explainerPLAIN TEXT
scope:     只做 pages/04 与 notes/04，不动 pages/index.html
read:      brief.json / owner_list.md / .skills/anything2explainer/SKILL.md
facts:     只用已核实的来源；核不到就写 evidence_gap
deliver:   pages/04/index.html
           screenshots/04-desktop.png (1440×900)
           screenshots/04-mobile.png  (390×844)
           notes/04-anything2explainer.md
accept:    中文 / 无 console error / 无登录支付表单 / 技法能指到具体段落
return:    路径 + 做了什么 + 缺什么 + 需要主线决定什么
# 不包含：发布、登录、改别人的页面、编造数据

问答

交出去之后，
主线做什么。

子代理失败了，主线要重做吗？+

先看回传：失败在哪一步、有没有留下可用的中间产物。能局部补就局部补；整个方向错了才重开，并把失败原因写回任务包。

怎么防止子代理改到别人的文件？+

在任务包里写死 scope，只给它的目录写权限；索引、报告这类共享文件由主线统一合并，子代理只回传自己的行。

子代理说「做好了」，能信吗？+

不能只看这句话。要看路径在不在、截图尺寸对不对、控制台有没有 error、验收锚点逐条过不过。回传格式里要求写「缺什么」，就是为了逼出没做完的部分。

为什么时间线要能拖？+

因为委派不是黑箱。播放头拖到 6 秒，能看到子代理刚接手；拖到 14 秒，能看到产物回来。每一步都能对上一条轨道，才知道时间花在哪。

让子代理去跑，
让主线留在判断上。

拆得清、给得足、收得回。委派的价值不是省掉人，是把人的注意力留给需要判断的那几步。
