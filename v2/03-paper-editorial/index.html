01PROCESS / 工序

四道工序，
少一道都不算做完。

读、做、查、交。顺序不能换，因为后一步要拿前一步留下的文件对照。不是凭印象说“差不多了”。

01 / READ

读规则

先看这份活该用哪份技能。里面写着触发条件、硬规则、禁止项，以及做完要交什么。

读的是文件，不是记忆里的印象。
02 / MAKE

做东西

按步骤动手，产物直接落在工作区。中途不猜结果；缺什么，就在缺口里写清楚。

能在本机打开，才写进交付。
03 / CHECK

自己查

拿同一份技能的验收条逐条对照：有没有漏项、有没有编数字、手机能不能看。

自检写成 self_check.md，不口头说。
04 / HAND OVER

交出去

页面、截图、文件清单、运行记录放在一起。做完只代表可以验收，发不发由人决定。

完成和发布，是两道闸。
02MEMORY / 记忆

你说过一次的不要，
它不该再问第二次。

这一批的需求里写着： 不要奶油底配珊瑚红。 它先读了这句，才开色盘。

被纠正过的口味会写成一条记录：不要什么、为什么、下一次怎么判断。下一次开工先读它，而不是重新问一遍。

记忆不是把聊天记录存起来。是把一次纠正压成一条下次能执行的规则，放在下次一定会读到的地方。

03DELEGATION / 委派

把一段活交出去，
主线继续走。

委派不是许愿。要写清边界、回件格式、停在哪里，再开一段新的上下文。回来的应该是一个能直接放进交付物的结果，而不是一堆过程。

图只是结构示意：主线和支线各自有上下文，靠一份写清楚的交接单接上。

RETURN / 回件A

拆参考

读三份参考，各留一条能直接用的做法：版式怎么切、字怎么进、手机先看哪一处。原文件不动。

回件格式：
1. 做法一句话
2. 用在本页哪一段
3. 不采用的部分与原因

05HANDOVER / 交付

做完，留下能查的账。

一页 HTML 不是全部。运行记录、文件清单、自检表放在一起，别人才知道这东西怎么来的、还缺什么。

文件在，才叫交付。文件不在，只是一段演示。做完之后，页面、两张截图、清单和自检放在同一个目录里；缺口也写进去，不拿“差不多了”盖过去。

可复查

说明书不是保证书。

它不保证每次都对。它保证动手之前读过规则，做完之后拿同一份规则对照；不对的地方写进缺口，不写成成绩。下一页也一样，先跑一遍，再说话。
